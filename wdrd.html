WDRD

Wii Digital Resource Description is a proposed Wii-specific technical metadata framework for describing WiiWare, Virtual Console, and Wii Channel titles, their TMD data, content structures, and installed representations. It supports structured technical research, including reverse-engineering and modding investigations.

STATUSPLANNED

Targeted for the MarcViiew 0.9 BETA era alongside the planned UI update. No formal schema has been finalised yet.

WHY WDRD?

Describe the digital object behind the catalogue record.

MARC 21 gives MarcViiew a bibliographic encoding format, while RDA and related cataloguing principles provide ways to think about resources, attributes, and relationships. WDRD is intended to describe Wii-specific technical structures and platform metadata that those general standards do not attempt to model.

IDENTIFICATION

What is this title?

Title IDs, title type, region, version, and other stable platform identifiers.

TECHNICAL

What does the platform say?

TMD information, content counts, boot indices, content types, sizes, hashes, and related title metadata.

REPRESENTATION

Where is it?

Observed NAND paths, title-local content, shared content, WAD representations, and distinctions between logical and physically observed content.

EVIDENCE

How certain are we?

Separate confirmed format knowledge, hardware observations, strong inferences, hypotheses, and unresolved questions.

INFLUENCES & REFERENCES

Related standards, distinct purposes.

WDRD is an independent technical-description framework. Existing cataloguing standards inform its descriptive context, while other specifications may be consulted comparatively for documentation and modelling techniques. A reference is not automatically an adopted model.

01MARC 21

Bibliographic encoding and a way to connect WDRD research with conventional catalogue records; not the technical schema for TMD or content structures.

02RDA

Conceptual context for describing resources, attributes, and relationships.

03AACR2

Historical cataloguing context and comparison point.

04PREMIS — reference only

Consulted for examples of formal metadata modelling and element documentation. PREMIS is a digital-preservation standard; WDRD does not implement it, claim conformance, or adopt its data dictionary wholesale.

PROPOSED MODEL

A layered description.

BIBLIOGRAPHIC

Resource identity

Title, creators, publisher, platform, release information, and other ordinary descriptive metadata.

WII PLATFORM

Title metadata

Title ID, TMD, ticket relationships, title version, required system information, and content inventory.

PHYSICAL / DIGITAL

Representation

Installed NAND representation, content objects, shared resources, WAD or SD representations, and observed paths.

TECHNICAL EVIDENCE

What do we know?

Sources, observation methods, test conditions, confidence levels, and unresolved questions help distinguish confirmed platform behaviour from inference and hypothesis.

ROADMAP

WDRD is deliberately not being finalised yet.

01Build the evidence base

Continue documenting NAND, TMD, content, WAD, WiiWare, and Virtual Console behaviour across real titles.

02Identify stable attributes

Separate platform facts from title-specific observations and avoid turning current hypotheses into schema requirements.

03Draft WDRD 0.1

Define fields, definitions, datatypes, required/optional status, provenance, evidence levels, and examples.

04Test through the UI

Use the MarcViiew 0.9 BETA interface to determine which WDRD information is actually useful to catalogue users.

STATUS

Planned, experimental, and intentionally open.

WDRD is a proposed project of the MarcViiew ecosystem. It is not an official Nintendo, MARC, RDA, AACR2, Library of Congress, or other standards-body specification.
